# Islam Dairy Manager — التثبيت والتشغيل (بالعربية)

## المتطلبات
- **Node.js 22 LTS** (ملف `.nvmrc` يحدد 22). لا تستخدم Node 24 — سبب خطأ `spawn UNKNOWN` من esbuild (راجع `docs/TROUBLESHOOTING_ESBUILD_NODE24.md`).
- **pnpm 9.x** (المشروع مضبوط على `pnpm@9.7.0` في `packageManager`). إن كان عندك pnpm 11 فثبّت 9: `npm i -g pnpm@9.7.0`.
- Prisma مثبّت على **5.22.0** — لا تغيّره.

## التثبيت (أول مرة)
```bash
nvm use 22                      # أو nvm-windows: nvm use 22.x
pnpm install                    # سيُنشئ pnpm-lock.yaml (غير مرفق، انظر التقرير)
cp .env.example .env            # ثم عدّل SESSION_SECRET (16 حرفاً على الأقل)
pnpm db:generate                # توليد Prisma Client
pnpm db:deploy                  # تطبيق كل الـ migrations (آمن على قاعدة موجودة، لا يحذف بيانات)
pnpm db:seed                    # أول مرة فقط: ينشئ الصلاحيات والأدوار والمستخدم admin
```
> على قاعدة بيانات **موجودة** فيها بيانات حقيقية: نفّذ `pnpm db:deploy` فقط (لا تنفّذ `migrate reset` ولا `db push`).
> انسخ ملف القاعدة احتياطياً قبل أي ترحيل.

## التشغيل
```bash
pnpm backend      # الخادم على http://localhost:4000
pnpm frontend     # الواجهة على http://localhost:5173  (في نافذة ثانية)
```

## الدخول الأول
- المستخدم: `admin` — كلمة المرور الافتراضية للـ seed: `ChangeMe123!`
- **غيّر كلمة المرور فور الدخول الأول.** هذه قيمة افتراضية للبدء وليست سراً حقيقياً.

## متغيرات البيئة (`.env`)
| المتغير | مطلوب | الوصف |
|---|---|---|
| `DATABASE_URL` | نعم | مسار قاعدة SQLite، مثال `file:./database/dev.db` |
| `SESSION_SECRET` | نعم | نص عشوائي طويل (≥16 حرفاً) لتوقيع الجلسات. لا تضع قيمة حقيقية داخل git |
| `PORT` | لا | افتراضي 4000 |
| `NODE_ENV` | لا | `development` أو `production` |
| `APP_VERSION`, `APP_NAME`, `STORE_NAME_AR` | لا | معلومات العرض |
| `ANTHROPIC_API_KEY` | لا | للمساعد الذكي فقط؛ اتركه فارغاً لتعطيله (لم يُغيَّر المساعد) |
| `ASSISTANT_MODEL` | لا | نموذج المساعد |
| `VITE_API_URL` | لا | في الواجهة فقط، افتراضي `http://localhost:4000/api` |

## فواتير الموردين — كيف تعمل
- **فاتورة شراء**: تزيد المخزون (حركة IN، السبب PURCHASE) وتسجل الباقي ديناً للمورد.
- **دفعة على فاتورة** (من صفحة الفاتورة أو صفحة المورد): ترفع المدفوع وتخفض المتبقي في **الفاتورة نفسها**، والحالة تتغير تلقائياً: غير مدفوعة ← مدفوعة جزئياً ← مدفوعة.
- **دفعة عامة**: تخفض رصيد المورد دون ربطها بفاتورة (مثل شراء الحليب).
- **الإلغاء**: يعكس المخزون (حركة OUT، PURCHASE_CANCELLED) ويُخرج الفاتورة **ودفعاتها** من رصيد المورد والصندوق والتقارير. يُرفض الإلغاء إن كانت البضاعة بيعت/استُهلكت.
- **منع التكرار**: النماذج ترسل مفتاحاً فريداً؛ إعادة إرسال نفس الطلب (نقر مزدوج/إعادة محاولة) لا تُنشئ فاتورة أو دفعة ثانية ولا تكرر حركة المخزون.
- شراء الحليب (`MilkPurchase`) نظام منفصل ولم يتغيّر، ولا يُحتسب شيء مرتين بين النظامين.

## الفحوصات المتاحة
```bash
pnpm verify                     # فحوصات بدون npm (Python 3 + Node ≥ 22.18؛ يعيد رمز خروج ≠ 0 عند أي فشل): قاعدة البيانات، المسارات، المحاسبة، السيناريوهات
pnpm test                       # اختبارات vitest الكاملة (تحتاج pnpm install)
pnpm build                      # بناء كل الحزم مع فحص TypeScript
```
